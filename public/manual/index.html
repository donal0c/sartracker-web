SAR Tracker Operator Manual

How to run a search in SAR Tracker: start the mission, follow your teams on the map, mark what you find, and close the mission safely. Written for volunteers, in the order you will need it.

Start here

Team betas are for controlled testing. Keep your normal operational process running beside SAR Tracker. If the screen and your independent source disagree, trust the independent source and stop using SAR Tracker's output until you know why. A calm-looking screen is not proof that the data is current.

The 6-step start

  1. Open SAR Tracker. Confirm the tracking strip is green. If it says Tracking is not configured, go to Settings first.
  2. Type a Mission name your coordinators will recognise later.
  3. If the search began before you opened the app, set Start offset (hours) (up to 48).
  4. Tick the groups and devices taking part before you press Start.
  5. Press Start.
  6. Check the chip says ACTIVE and your teams are on the map.

The full detail is in Run a mission.

Run a mission

Start a mission

  • Mission name: required. Use plain words, for example the place and date.
  • Start offset (hours): backdates the start when the search began before you opened the app. Maximum 48 hours.
  • Mission participants: nothing is pre-selected. Tick the groups and devices that are part of this search. A group covers everyone in it; their own boxes are locked and say included by selected group.
Earlier history is only fetched for people you tick before Start. If you use a Start offset, tick everyone who was out during that time first. Someone you add after Start needs an explicit History from choice (below). If you start with nobody ticked, the app allows it and says so: those devices' positions are not saved as mission evidence or shown on the mission map until you add them.

When you press Start, the chip turns green ACTIVE and the timers run. The Active timer is search time; Elapsed is total time since the (possibly backdated) start.

Add or remove a team during the mission

  1. In Participants, choose Individual device or Traccar group, then pick one from the list.
  2. Choose History from. There is no default, and Add participant stays greyed out until you choose:
    • Mission start: brings in their track back to the mission start.
    • Now: records only from this moment.
    • Custom: from a time you enter.
  3. Press Add participant.

Choose carefully: Mission start could count a late joiner's earlier travel as part of this mission. To take someone out, press Remove on their row. That stops collecting from now on; what is already saved stays saved.

History backfill: pending / retrying means the earlier track is still being fetched from the tracking server. You cannot finish the mission until it completes. If it stays pending, check the tracking strip.

If someone joins or leaves a selected group on the tracking server, an amber notice appears (for example 2 joined Hill Team) saying no earlier evidence was invented. Read it, then press Acknowledge membership notices.

Outings

An outing is a period you name and control, such as Morning search. The app never starts or ends one for you.

  • Type a name and press Start outing. Press End now when the period ends. Edit changes the boundaries; it never changes recorded positions.
  • Outings can cross midnight but cannot overlap.
  • With no outing running, new positions are kept as Unassigned. That is normal and not an error.
  • Pausing the mission does not end the outing.

Pause and resume

Pause stops the Active search timer; Elapsed keeps running. While paused, live position refresh is suspended, so the map does not update. Press Resume to carry on.

Finish

  1. Press Finish, then Confirm Finish (or Cancel).
  2. If an outing is still open, the dialog says so and offers End outing now. Finishing does not invent an end time for it.
  3. The mission returns to IDLE and a Mission Governance card appears so you can archive and lock it.
Finish can be refused. If participant history is still loading, or the app could not save evidence it has already seen, the mission stays active and a red message explains why (for example Mission cannot be finished while 2 participant history backfill checkpoint(s) are incomplete). Fix or wait, then try again. Do not treat a refused Finish as a cosmetic error.

If the app restarts or crashes

  • Resume keeps the same mission. A mission that was running carries on; one you had paused stays paused until you press Resume on the mission panel.
  • The gap between the interruption and your choice counts as paused time, and Review records it as an automatic pause after an unexpected shutdown.
  • Start Fresh abandons that recovery path. Use it only if the interrupted mission is not the current incident.
  • Keep one mission open across a multi-day search, even if the app or computer is closed overnight. Finish only at stand-down. Do not start a new mission each day to save space.

Make more room, or make it easier to read

  • Focus Mode (top bar) gives the map most of the window. Press Exit Focus to come back. The tracking strip stays visible.
  • Minimize (Mission Control header) shrinks Mission Control to one line: mission name, state, search timer, Review and Restore mission. Restore it to reach Pause or Finish. The app restores it by itself when something needs a decision.
  • Collapse (Layers tab) hides the whole right side. Restore workspace in the top strip brings it back. Your layer choices are kept.
  • Theme: Standard or High contrast. The choice is remembered on this computer.

Tracking and devices

SAR Tracker asks the Traccar server for positions about every 30 seconds (the interval is in Settings). If the server cannot be reached it keeps the last positions it had and marks them, rather than clearing the map.

If a map overlay (for example markers) fails to redraw, a persistent warning on the map names it while the app retries. Check against your independent source and export a support report if it stays.

Devices workspace

  • Filters along the top: Devices, Hidden, Online, Stale, NoFix. The search box searches inside the chosen filter.
  • Trail colour: click a swatch to pick a colour for that device's dot and trail.
  • Visible: untick Shown to hide a device's dot without removing it from the mission.
  • Zoom jumps the map to the device (not available if it has no fix).
  • The selected device panel shows status, Last seen, Fix time, source, GPS accuracy, battery, speed and coordinates. Times are local, with the time zone and UTC offset.
  • Reconnect reloads settings and reconnects to the tracking server. Until a device sends a fresh fix it shows Unknown / Last known, not Online.

Who is tracked, saved and shown is decided only by Participants in Mission Control. The Devices workspace does not change it.

Breadcrumbs: line or dots

  • Solid line draws each trail as a line. On very long routes the line may be simplified for speed; the app then shows Trail display simplified and how far the line may differ. The saved history is not simplified.
  • Breadcrumb dots shows every real fix as a dot. If there are more than 10,000, the Tracking tab shows one page at a time with Earlier and Later. A page never uses samples in place of real fixes.
  • Breadcrumb size changes line width or dot size for all devices.

To hide only a current-position dot or only a trail, use the Layers tab.

Stationary attention

An amber ring means a device has not moved meaningfully for a while. The defaults are 20 minutes and 15 metres (changeable in Settings under Mission Defaults). It is a prompt to check on them, not an emergency declaration. Acknowledge attention dims the ring but changes no data. Real movement clears it. A new stationary spell needs a new acknowledgement.

Mission history coverage

The thin violet lines on the map are the saved history of the people you have ticked. This panel tells you whether that history is complete. It never delays or hides live positions. It will not claim "all shown" unless the saved record backs it up.

MessageWhat to do
All mission history shownComplete for every selected participant and outing.
All selected history shownComplete for what is ticked, but you have left some people or outings out (see Layers below).
Participant history is still being addedWait. Live positions are unaffected. Finish stays refused until it completes.
History incomplete — showing loaded coverageLoading failed or was interrupted. What is drawn is real but not the whole record. Press Retry. Do not treat it as the full history.
Loaded history is shown, but completeness is not yet verifiedEverything may have loaded, but the final check has not passed. Press Retry.

Progress can go backwards (for example 0 of 0 briefly after a restart). A lower number is safer than a false 100%.

  • Inspect exact fixes switches to the paged breadcrumb dots view (see above).
  • In Layers, the Mission History checkboxes can leave out a person, a named outing, or Outside outings (fixes that fall in no outing). This only changes what is drawn; it deletes and changes nothing, and it does not hide anyone's live marker.
  • Devices that were never picked as participants stay out of mission evidence and the mission map.

Map and grid references

  • Maps lists Official Maps (Discovery Topo, Premium Basemap, Aerial Imagery, High-Resolution Imagery) and Public Fallback Maps (OpenTopoMap, ESRI World Topo, OpenStreetMap, ESRI Satellite). Official maps need the desktop app and a licensed package.
  • The map name shows below the list, with a health line. Public fallback only means it needs internet.
  • Check View tests whether the map you are looking at can be drawn from local files. Run it after you pan or zoom.

Coordinates

The strip at the bottom shows the position under the cursor as DD (latitude/longitude), Irish Grid (TM65) and DMS. Outside Ireland the grid field says Outside Ireland rather than inventing a reference.

  1. Choose the input type: IG, DD or DMS. (W3W is not available offline.)
  2. Type the coordinates and press Convert. Copy any result with Copy.
  3. Go To Location moves the map there (a red ring marks it briefly). Create Marker Here opens the marker form at that point.
  • Short grid references work: V 80 84 means the centre of that grid square.
  • Decimal degrees use a full stop for the decimal point. Commas are only allowed between latitude and longitude.
  • A point far out at sea, or a contradictory input such as a negative value tagged E, is refused with a message instead of being guessed.
  • Bearings: magnetic declination for Ireland is taken as 4.5° west. True to magnetic subtract 4.5°; magnetic to true add 4.5°.

Official and offline maps

Licensed maps are private team files. They are never in the public app or the hosted test copy. Public fallback maps need the internet in the desktop app. If you might work without signal, set up and check the official offline map before you go.
Not run in this refresh. The steps below come from the app's Settings screens and earlier verified releases. The file-picker buttons only work in the packaged desktop app, which this browser-based check could not open.

One-time setup (desktop app)

  1. Get the team's USB drive or folder with the MapGenie source file and the prepared .mbtiles map package.
  2. Open Settings → Official Maps.
  3. Press Choose MapGenie File and pick the source file.
  4. Press Add Discovery Package and pick the .mbtiles file. The app copies it into its own storage, so you can remove the USB afterwards.
  5. Press Save Settings and wait for the package to be checked.
  6. In Maps, choose Discovery Topo.

Raw Discovery files (.zip, .tif) are not accepted. An admin must prepare an .mbtiles package first. Packages are labelled Standard (under 2 GB, the Kerry/West area, recommended), Mission Area (2–4 GB) or National (over 4 GB, prepared in advance, never during a mission).

If beta 13.4 rejected the Discovery package, open Settings and press Save & Close to recheck it, or add it again. Beta 13.5 accepts that package.

Before you rely on it in the field

  1. Pan and zoom to the area you will search.
  2. Open Maps and press Check View.
  3. Read the Field Readiness result: Field ready (green), Partially ready (amber) or Not field ready (red).

Field ready applies only to the view and zoom you checked. Moving the map, changing map, or a tile failure clears it, so run Check View again. A hatched pattern on the map marks tiles that are missing locally.

SymptomWhat to do
Package shows missingThe file is no longer there. Re-import it from the USB.
Package shows unreadableThe file is damaged. Get a fresh copy from the map admin.
View is outside the packagePan to the search area, or import a wider package.
Official maps say Not configuredNo MapGenie file has been chosen yet (or you are in the hosted test copy, which only has public maps).

Export Readiness Certificate in Settings saves a text file about the package (sizes, zoom range, checks). It describes the package, not your current view.

Layers: show and hide things

The tree groups everything on the map: Tracking (Current Location and Breadcrumbs, listed per device), Mission History, Helicopters, Map Tools (markers by type, drawings by type, measurements) and GPX Tracks.

  • You can show a device's current position without its trail, the trail without the position, or both. A box with a dash means some devices are on and some are off.
  • Hidden things stay saved; you just cannot click them on the map. A warning stays on screen while any current location is hidden.
  • Search filters the tree. Show Hidden includes hidden items. Expand All / Collapse All and Refresh do what they say.
  • Select a row to inspect it. You can give it an Alias (a display name only), move it Up / Down among its siblings, or, for a drawing, press Edit Drawing.

Markers

To place a marker, click empty ground on the map when no tool is armed (dragging only pans the map). The marker form opens with the position already filled in as WGS84, ITM and TM65 grid reference.

TypeRecords
IPP/LKPInitial planning point or last known position, with subject category.
ClueClue type, confidence, found by, notes.
HazardHazard type and severity.
CasualtyName, Casualty Status (Lost, Crag Fast, Medical Emergency, Unknown, Deceased), Evacuation Priority (Normal, Urgent, Walk-Off, None, Self-Evacuation), found by, and a timestamped treatment log.
  • Casualty markers need Name, Casualty Status and Evacuation Priority before Save works. Missing ones are marked Required.
  • Treatment log: type each update in New Treatment Update and press Add Update. Each entry is timestamped and earlier ones are never overwritten.
  • Map label size changes the text on the map. Casualty labels start larger.
  • An evidence attachment (photo or file) can travel with the marker in the desktop app.
  • Retire asks twice (Retire, then Retire Marker; Keep cancels). A retired marker leaves the map but its history stays in the record.
  • If a marker sits on top of a drawing, clicking selects the marker. To edit the drawing underneath, use the Layers tab.
  • To place a marker from a grid reference instead of a click, use Marker at GR, or Create Marker Here in the coordinate converter.

Tools need an active mission (before that the box says Mission required). Pick one tool at a time. When you save or cancel, the map returns to its normal state (no tool armed). There is no separate Select button.

To correct a drawing, click it (or use the Layers tab), then edit or Retire it and confirm. Retiring removes it from the map but keeps its history.

GPX tracks and helicopters

Both live in the Tools tab.

GPX tracks

  • Import Files and Import Folder add tracks. Watch Folder imports new files as they appear, and Rescan Watches checks again. These need the desktop app.
  • Each imported track has its own colour. Retire takes it off the map but keeps the record.
  • Points with no time are kept as static evidence and are not placed at an invented time.
  • To link a track to an outing, type the coordinator's name in Coordinator name for outing assignments, then choose the outing on the track's row.
  • Limits: 8 MiB per file and 100 files at a time. A bad file is refused with a reason and reported, never shown as a clean import. Wait for one import to finish before starting another.
  • Finish and Archive are held back while a GPX import is unfinished.

Helicopters

There are four slots: Rescue 118, Rescue 115, Air Corps 1, Air Corps 2. Open a slot to enter call sign, HEX ID, latitude, longitude, altitude, speed, heading and last update. It needs a call sign and a valid latitude and longitude before it saves. Slots in use always stay visible. Hide empty slots tidies the panel. Show or hide helicopters on the map in Layers.

Review and Replay

Review (Mission Control header) opens the Audit Workspace: what the app has saved for a mission. Nothing in it changes the mission.

  • Close it with Close or Esc to get the map back. If a marker form is open on top, the first Esc closes the form.
  • With no active mission, Review opens full screen with a mission selector.
  • Tabs: Mission Details (counts, dates, the audit log), Replay, Search Passes, Marker Log, Layer Console.
  • The audit log hides raw position chatter by default. Tick Show tracking telemetry to see it.

Replay

  1. Open the Replay tab.
  2. Set Selected local time (Europe/Dublin) and press Replay data known at this time.
  3. Read the small map: exact dated breadcrumbs, the last known position at that time, dated GPX points, and markers and drawings. Click a feature to see what it is and when.
  4. Tick or untick the categories to focus. This only changes the Replay map.
  5. Press Return to Live / now to leave.

Replay is read-only and never touches the live map. It does not replay your old zoom or panels; it shows evidence. Future times are refused. A time that does not exist (clocks going forward) is refused. In the repeated autumn hour you are asked to choose which one you mean. If something is missing or could not be drawn, Replay says so instead of showing a clean map.

Search Passes

Here a coordinator records who searched which area, and how it went. Choose the coordinator, search area, outing and assignment yourself (nothing is picked for you), enter the pass start and end times (Europe/Dublin), then choose the outcome: fully searched, partially searched or aborted. The outcome is always the coordinator's declaration. Any coverage figure from breadcrumbs is advice only and never sets the outcome. A pass must sit inside its outing and cannot be in the future. Finished missions show these records but do not accept new ones.

Archive and lock a finished mission

After Finish, archiving makes a single encrypted copy of the mission, checks it, and locks the mission so it cannot change. Do it at stand-down, not mid-search.

A lost recovery code cannot be recovered. Each archive gets one code, shown once. Store it under your organisation's approved procedure before you continue. The dialog has no Copy button. The passphrase and the code are the only ways to open the archive later.

Archive & Lock

  1. Find Mission Governance in Mission Control. It acts on the mission named there, which starts as the one you finished most recently. If several missions are finished, choose the right one in the Mission list and check the name before you go on.
  2. Press Archive & Lock.
  3. Type an archive passphrase twice. Use at least 14 characters with at least three of: lower case, upper case, numbers, symbols. Press Generate one-time recovery code.
  4. Write the code down safely. Type it back exactly in the confirmation box.
  5. Press Create, seal, and verify archive and wait.

The app creates the encrypted archive, seals it (this locks the mission read-only), then restores those saved bytes into a scratch area and checks them independently. If creating or checking fails, it says so and your live data is untouched. A sealed but unverified archive stays locked and marked incomplete; retry it from Review with the original passphrase and recovery code. Do not call it archived until Review shows Verified encrypted archive.

Making and checking an archive, and opening one in Review, use temporary readable copies on this computer. The app removes them when it finishes. After a crash they can stay until the app restarts. Archive encryption does not encrypt the live mission database. Protect the computer and its login.

Open an archive (read-only)

  1. Open Review and find the mission under Saved Mission Archives.
  2. Select the archive, choose Passphrase or Recovery code, enter it, and press Open Read-only Archive.
  3. The banner says Archived mission - read-only and shows the archive's SHA-256. Look around, use Replay.
  4. Press Close Archive Review when finished so the temporary copy is removed. If it warns that cleanup failed, use the retry.

Restore for correction needs an authorizing admin and a reason. It opens a new live revision; the earlier archive is never changed. Admin Unlock on the Governance card also needs a named admin and a reason. Use both only when your coordinator tells you to. Older archives labelled Legacy unencrypted open without a passphrase, and are not upgraded.

Archive cleanup (optional)

Review Archive Cleanup removes the mission's bulk rows from the working database after re-checking the verified archive. The mission stays listed and can still be opened from the archive. You must type the archive's credential again and the mission name. It frees space for reuse; it is not secure erasure. Keep the archive file and its passphrase or recovery code: recovering those rows depends on them. Do not run cleanup during operations.

If the app says evidence was lost

If the app knows some evidence could not be saved (for example after a crash), the mission is marked so it can never claim to be Complete or 100%. To archive anyway, a named admin records the gap.

This records who accepted the gap. It does not restore evidence, and the warning stays with the mission. If the admin list is empty, add the admin in Settings → Mission Defaults → Admin roster, press Save & Close, and you return to the same dialog with your typing kept.

Settings

Open Settings from the top bar. If you close it with unsaved edits the app asks whether to keep editing or discard. The bar at the bottom has Test Connection, Save & Close and Save, Connect & Close.

Connect to Traccar

  1. Under Data Sources, choose provider Traccar HTTP.
  2. Enter the Provider base URL your admin gave you. Do not put a username or password in it; such URLs are refused.
  3. Choose Basic (email and password) or Bearer (token) and fill it in.
  4. Press Test Connection. It signs in and checks device access.
  5. Press Save, Connect & Close. Tracking connects and you return to the map.

The password or token is kept in the app's own local credential file (not the operating system's keyring) and is cleared from the form after saving. If tracking says no credential is available, enter it again here.

Mission defaults, rosters and weather

  • Auto-refresh interval (seconds) and Auto-save interval (seconds): both default to 30.
  • Stationary attention window (minutes) and movement floor (metres): defaults 20 and 15. Change them only on purpose.
  • Primary and Backup mission root: where mission files are kept. Leave blank unless an admin tells you otherwise.
  • Coordinator roster and Admin roster: names, one per line (commas also work). Coordinators are the people named in your records. Admins can record evidence gaps and unlock missions. These are lists of names for the record; they are not passwords, so treat Settings as trusted-computer access.
  • Coordinate display mode: Lat/Lon first or TM65 first.
  • Official Maps: see Official and offline maps.
  • Weather Links: press Add Weather Link for a named link such as Met Éireann. It appears in the Weather menu and opens in your normal browser. SAR Tracker does not fetch or forecast weather itself.

When something looks wrong: Diagnostics and support

Open Diagnostics in the top bar. It shows runtime and app version, mission phase, storage health (including Evidence health), the tracking snapshot and the current configuration. Diagnostics never shows passwords or tokens, and never shows the paths of map packages.

  1. Take a screenshot of what you see, if you can.
  2. Note the time it happened.
  3. In Diagnostics, enter that time in Incident time and press Export Incident Bundle (it covers 30 minutes either side). For a general problem press Export Support Bundle.
  4. Send the file with a few words on what you were doing. Look at it first: remove anything private, such as exact locations of a casualty, before sharing it outside the team.
  • Copy Report and Export Report give the readable report shown at the bottom of the page.
  • If the app closed unexpectedly last time, an amber notice at the top of Diagnostics offers a direct Export Support Bundle button. It never blocks an active mission.
  • Bundles are saved on this computer only. Nothing is sent anywhere automatically. In the browser test copy the bundle holds only a basic environment snapshot.
  • A small amber Autosave warning in the top bar means the automatic backup is stale or failed. Keep the app open and export a bundle. A backup that fails around Start, Pause, Resume, Finish, Archive or Unlock shows a persistent alert below the top bar; do not treat the backup as current until it clears.

If SAR Tracker freezes (Linux)

If the clock still moves but clicks and keys do nothing, leave the app open. Do not restart, reinstall or force-close it. In a terminal run the report-only collector: 

sh "/opt/SAR Tracker Electron Validation/resources/field-tools/sartracker-linux-hang-collector.sh" --screenshot

For a running AppImage, find it with find /tmp -maxdepth 4 -path '*/resources/field-tools/sartracker-linux-hang-collector.sh' -print -quit and run it with sh and --screenshot. It reads process and graphics state and does not attach to the app or copy mission data. Review the optional screenshot before sharing it (it may show the map), then send the .tar.gz with the time and what you tried.

If it will not start

  • A separate startup fault window means a safety check failed before the mission screen opened. Read it, close it, and do not edit or delete the profile. Ask the maintainer.
  • SAR Tracker could not restart safely or could not close safely: leave the app as it is, keep the profile untouched and contact the maintainer rather than forcing it closed.
  • A database made by a newer version is refused with SAR Tracker could not start. Install a matching build; do not downgrade the profile in place.
  • Only one SAR Tracker runs at a time. If you see two windows, close the extra one.
  • Log files: Linux ~/.config/sartracker-web/logs/ and crashes/; macOS ~/Library/Application Support/sartracker-web/; Windows %APPDATA%\sartracker-web\.

Team beta notes

Internal beta only. Desktop betas are for controlled team testing. They are not code-signed and are never a production or sole-source incident tool. Passing the release checks covers only the testing scope written in that beta's release note.

Install a desktop beta

  • Use only a beta that has a release note (under docs/releases/ in the project). If the maintainer has not pointed you to one, ask before opening the app.
  • Every beta ships with a SHA256SUMS file. Check your download against it before running it.
  • Linux (the current CI beta): an .AppImage (portable) and a .deb (system install), both x86_64. AppImage: sha256sum -c SHA256SUMS --ignore-missing, then chmod +x the file and run it. If you see libfuse.so.2 errors, install libfuse2t64 (Ubuntu 24.04 / Debian 13) or libfuse2 (Ubuntu 22.04 / Debian 12). The .deb: sudo apt install ./<file>.deb.
  • Windows: an unsigned installer, only if the maintainer says a Windows build exists for that beta. Windows shows a "Windows protected your PC" warning: More info → Run anyway. Managed machines that block it cannot be worked around; use another computer.
  • macOS: built locally and supplied by the maintainer. If Gatekeeper refuses it, try right-click → Open first. Only if the maintainer asks, remove quarantine with xattr -dr com.apple.quarantine /Applications/sartracker-web.app. Never do that for an app from an untrusted source.

The hosted test copy

  • It is at https://sartracker-web.vercel.app/?missionHarness=1 and is for training and quick surface checks only. It keeps mission data in the browser session, has no official maps, and cannot use file pickers or restart recovery. Never use it for a real incident.
  • Confirm the amber Browser testing mode banner and Browser test / Session storage only in the top bar.
  • In Settings → Data Sources use the team's https Traccar address (from your admin), Basic login, Test Connection, then Save, Connect & Close. A plain http:// address is blocked from this page. After a full page reload, enter the password again.
  • If breadcrumb history looks empty, restart the mission with a 24 or 48 hour Start offset and tick the teams before Start.
  • When you report something, include the URL, mission name, browser, what you expected and what happened, and a screenshot if you can. The checklist is docs/team-testing-feedback-loop.md.

Using a beta beside your normal process (shadow use)

In shadow use the team's existing process stays in charge of positions, tasking and records. SAR Tracker is a second opinion. Before a field session, the release note must name the exact build, the existing process, the person running it, and a rehearsed switch back to that process that takes no more than 60 seconds. If any of that is missing, do not run a shadow session.

Say STOP SHADOW for: a current position you cannot explain, evidence lost or corrupted, a false Complete or 100%, controls that do not respond, the map disagreeing with its source, a privacy concern, or any doubt about archive or restore. The person running the existing process takes over and the SAR Tracker operator stops using its output. Keep the app and profile as they are, if that is safe. Never promote SAR Tracker to primary to cover a gap.

Record good exercises as well as faults. Ordinary wording or layout feedback needs a short note and, if you like, a cropped, redacted screenshot. Never share a raw mission database, a whole profile, a precise location, a credential, a private map, or an unchecked screenshot as routine feedback.

Known issues and limits

This list is kept honest on purpose. It is safer to know what is not finished than to assume it.

Things that can catch you out

  • Public fallback maps do not work offline in the desktop app. Only an imported official map does.
  • Paused means no live refresh. The map does not update until you Resume.
  • Field ready covers only the view and zoom you checked.
  • W3W (what3words) conversion is not available.

Limits of this beta

  • Coordinator and admin rosters are lists of names for the record. They are not logins, so anyone who can open Settings can change them. Treat Settings as trusted-computer access.
  • Replay reconstructs what was known at a time. It does not reproduce your old screen layout or zoom.
  • Archive encryption protects the archive file, not the live database, and archive steps use temporary readable copies (see Archive and lock).
  • Only Linux desktop betas are produced by the release pipeline. Windows and macOS builds are supplied separately, and signing and notarizing are still open work.
  • The hosted test copy keeps data in the browser session only and caps very large histories.
  • This manual was checked in a browser test copy with made-up data. It did not run: the official map file pickers, GPX file pickers, marker file attachments, real archive encryption on disk, support and incident bundle export, the Linux freeze collector, startup faults, or live Traccar. Those descriptions come from the app's own labels, code and earlier verified releases. If one of them differs on your desktop, tell the maintainer.

Maintaining this manual

Change this file whenever anything a volunteer can see changes. Describe what the app does today, not what is planned. Put anything unfinished under Known issues.
